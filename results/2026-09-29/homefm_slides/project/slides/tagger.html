Architecture

A sentence instead of learned weights

DomusFM

score(Cook) = W_Cook · vector + b_Cook

W_Cook is learned from labelled cooking examples. A new activity needs new weights: labels and training.

HomeFM tagger

score = σ( a · cos( P(minute), Q(text(“someone is cooking”)) ) + b )

P, Q, a and b are shared by all activities. The only activity-specific part is the sentence.

Toy example: minute 18:31 projected to [0.85, 0.15, 0.05]

SentenceSentence vectorScore
“someone is cooking food”[0.9, 0.1, 0.0]0.78 ← highest
“someone is sleeping”[0.0, 0.1, 0.9]0.06
“someone is vacuuming”[0.1, 0.9, 0.1]0.23

P: 256 → 256 → 128 (~99k weights). Q: 384 → 384 → 128 (~197k). Both normalised to length 1.

It only works because game 3 trains minutes and sentences into one space. Bolting a sentence head onto DomusFM would not work.

Several activities can be on at once: each sentence is scored separately.

The same trick is used at both ends: devices are sentences at the input (an ingredient), activities are sentences at the output (a comparison target).
