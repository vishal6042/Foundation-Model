From model to answers

The query agent: text in, tools, text out

Bridge 1 · stored facts (main path)

Heads turn vectors into rows with text labels: episodes, states, anomalies, device health. The agent answers with plain SQL, e.g. count_episodes(cooking, 16:00, 20:00).

Bridge 2 · search by meaning (open path)

Projected minute vectors in a vector index (1,440 × 128 × fp16 ≈ 370 KB per home per day). semantic_search: text in, JSON out; the tool does the vector maths.

Rules

The LLM never produces numbers; tools do · time resolved in code, in the home's timezone · every answer has evidence and confidence · unobservable concepts are refused honestly.

Example, open path

“Did anyone vacuum today?” Not a stored concept, but a vacuum plug exists → search “someone vacuuming” → 10:05–10:38, living room, score 0.78, plug at 1.2 kW → “Probably yes, ~10:05–10:38 (medium confidence)”.

Tools: query_events · query_episodes · get_state · semantic_search · compare_baseline · detect_anomalies · device_health · energy_breakdown · forecast · list_capabilities. Model: a small local 3–8B LLM with function calling; cloud only if the household opts in.
